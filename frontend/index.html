02 — AI Agent Platform

Deploying AI Agents as Tier-1 Services

An agent in production is a distributed system with a model dependency. This is the platform-engineering playbook I apply so agents ship safely and stay up — reliability, security and observability before launch, not after the incident.

01

Containerise & Harden

Agent and tool services built as minimal, pinned container images with image scanning and SBOM generation in the pipeline — the same supply-chain gates that keep zero HIGH/CRITICAL CVEs out of banking production apply to every AI service image.

DockerSBOMImage scanningPinned bases
02

Provision with IaC

Agent environments — AKS namespaces, networking, identity, secrets — defined as versioned Terraform and Bicep modules with workspace-separated environments. Reproducible, reviewable, and up in under 20 minutes; no click-ops.

TerraformBicepWorkspacesReusable modules
03

Secure by Default

Azure OpenAI and other model endpoints reached over private endpoints and VNet isolation, credentials in Key Vault, access governed by Entra ID RBAC and least privilege — the controls a regulated bank requires before any LLM touches internal data.

Private endpointsKey VaultEntra IDVNet isolation
04

Ship via GitOps

Helm + Argo CD drive declarative, auditable releases from Azure DevOps or GitHub Actions pipelines. Rolling, blue-green and canary strategies give zero-downtime deploys and a one-command rollback to the last good version.

Argo CDHelmCanary / blue-greenRollback
05

Scale & Protect Capacity

Resource requests and limits, HPA and Cluster Autoscaler sized to real load, and timeouts and retry budgets on every model call — so a slow or rate-limited model dependency degrades gracefully instead of cascading through the cluster.

HPACluster AutoscalerTimeoutsRetry budgets
06

Observe Everything

Prometheus, Grafana and Azure Monitor for the golden signals — latency, errors, traffic, saturation — plus agent-level telemetry on model latency and tool-call outcomes, with structured logs that let an engineer reconstruct what an agent did and why.

PrometheusGrafanaAzure MonitorStructured logs
07

Define SLOs & Respond

SLIs and SLOs for agent availability, latency and error rate, error budgets that steer release pace, and alerting tied to on-call runbooks — the same practice behind 99.9% reliability for critical banking services and a 25% MTTR reduction earlier in my career.

SLO / SLIError budgetsOn-callMTTR
08

Guardrails & Fallbacks

Circuit breakers, graceful degradation and human-in-the-loop escalation paths when an agent or its model is unavailable or unsure. Audit logging on actions so security and compliance teams can review agent behaviour after the fact.

Circuit breakersFallbacksEscalationAudit logging
Reliability is a featureSLOs agreed before launch; error budgets decide how fast we ship.
